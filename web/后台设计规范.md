# Admin 后台设计规范

版本：1.0  
更新日期：2026-10-08（Asia/Shanghai）  
适用范围：`web` 项目的 `/admin` 管理中心及其登录、详情、弹窗和抽屉。

本文件是后台设计与前端开发的统一依据，不适用于访客聊天页或独立的 `website` 官网。第一版基于现有 Vue、Tailwind CSS、Reka UI 和 Lucide 组件体系，不更换框架。

本文中的尺寸、变量和组件规则是目标规范，不表示全部已在代码中实现。现有差异采用逐步收敛方式处理；本次仅建立文档，不修改界面、接口、权限或数据库。

## 1. 设计定位

后台面向运营、内容维护和系统配置，优先保证信息清晰、操作明确、数据可信。

- 使用蓝色主操作、白色内容面、浅灰背景和细分隔线。
- 信息密度适中；通过对齐、文字层级和分组建立秩序，不通过增加卡片、阴影和装饰制造层次。
- 与官网保持不同的视觉气质，不继承官网的大标题、场景图、深绿色主视觉和营销动效。
- 品牌名称由现有品牌配置提供，不在页面中重复硬编码或随样式调整更名。
- 设计调整不能扩大权限、隐藏错误、虚构数据或改变业务状态的含义。

## 2. 设计变量与视觉基线

### 2.1 颜色

以下为后台语义变量的目标映射。后续统一样式时，应集中定义并限定在后台作用域；不要通过全局 `:root` 覆盖聊天或官网变量。

| 目标变量 | 基线值 | 用途 |
| --- | --- | --- |
| `--admin-primary` | `#2457E6` | 主按钮、选中状态、功能链接 |
| `--admin-primary-hover` | `#1F46BD` | 主操作悬停 |
| `--admin-primary-soft` | `#EEF4FF` | 轻量选中背景 |
| `--admin-canvas` | `#F8FAFC` | 页面底色 |
| `--admin-surface` | `#FFFFFF` | 表格、表单、浮层内容面 |
| `--admin-text` | `#172033` | 标题与主要内容 |
| `--admin-text-secondary` | `#64748B` | 辅助信息与字段说明 |
| `--admin-border` | `#E2E8F0` | 分隔线、输入框与内容边界 |
| `--admin-success` | `#25825C` | 成功、可用状态 |
| `--admin-warning` | `#946200` | 待处理、风险提示 |
| `--admin-danger` | `#B42318` | 错误与危险操作 |

状态背景与文字色成对维护；不能只改变背景，造成文字不可读。浅色边界不承担唯一的状态表达。正文对比度以至少 4.5:1 为验收目标，交互焦点及必要图形至少 3:1。

### 2.2 字体

沿用系统中文无衬线字体与现有字体回退，不为后台引入额外在线字体请求。

| 层级 | 桌面字号 | 字重 / 行高 |
| --- | --- | --- |
| 页面标题 | 30px；小屏 24px | 600 / 1.3 |
| 区块标题 | 18px | 600 / 1.4 |
| 卡片标题、重点字段 | 14px | 600 / 1.5 |
| 正文、表格内容、按钮 | 14px | 400–500 / 1.5–1.7 |
| 字段标签、辅助信息、表头 | 12px | 400–600 / 1.5 |
| 统计主数值 | 28px | 600 / 1.2 |

- 不使用 10–11px 作为常规表格、字段说明或错误提示字号。
- 长标题允许换行；列表摘要可以截断，但详情必须能读取完整内容。
- ID、模型标识和代码可使用等宽字体；统计数值使用等宽数字，避免更新时跳动。
- 移动端文本输入控件使用至少 16px 字号，避免浏览器聚焦自动缩放。

### 2.3 间距、圆角与阴影

- 间距使用 `4 / 8 / 12 / 16 / 24 / 32 / 48px` 档位。
- 页面内边距：桌面 32px、中等宽度 24px、手机 16px；由布局容器统一设置。
- 页头与工具栏间距 24px，工具栏与内容间距 16px，常规区块间距 24px。
- 常规按钮和输入框高 40px；手机点击目标至少 44×44px，可通过扩大交互区域实现。
- 控件圆角 8px，内容面圆角 12px，弹窗圆角 16px，状态标签圆角 6px。
- 表格、普通卡片优先使用细边框，不使用大面积阴影。
- 下拉菜单、弹窗和抽屉可使用轻阴影；同级浮层保持一致。

## 3. 全局布局与导航

### 3.1 管理中心外壳

结构为：全局 Header → 左侧导航与右侧内容区。外壳限定视口高度，导航和内容分别管理滚动，不让长内容撑开整个应用。

- 全局 Header 基线高 60px，主要展示品牌和管理员身份，不恢复全局后台搜索框。
- 桌面侧边栏基线宽 240px；目录文字、图标和分组标题使用统一左对齐网格。
- 页面内边距只由外壳提供，业务组件不再重复增加同等外层 padding。
- 详情、弹窗内的内容间距不等于页面外层 padding，不能用取消所有间距的方式“修复对齐”。

### 3.2 导航分组

沿用当前信息架构：

- 独立入口：概览。
- 业务管理：会话管理、知识库、产品管理。
- 平台配置：Agent 配置、模型服务、Embedding 服务、接入管理。
- 系统管理：管理员、角色权限。

不重新增加“工作区”；分组不折叠。仅渲染当前账号有权访问的项目，隐藏后不留下空分组。操作记录若增加独立入口，应归入系统管理，但不因设计文档而自动新增功能。

激活状态仅改变颜色、背景和定位标记，不改变 padding、宽度、缩进、图标尺寸或菜单排序。标记使用绝对定位或预留空间，禁止激活时向右移动。

小屏导航保留访问全部已授权菜单的能力，可以沿用可滚动的横向导航；不将桌面侧栏压缩到无法阅读，也不依赖悬停访问子项。

## 4. 页面模板

### 4.1 统一页头

所有管理页复用 `src/ui/AdminPageHeader.vue`：左侧标题和必要状态，右侧页面操作；详情页增加明确的父级返回入口。

- 一个页面只有一个主要 `h1`。
- 不添加重复品牌头部、英文眉题或无必要的说明段落。
- 操作顺序固定：辅助操作在前，主操作在后；同一区域只有一个突出的主按钮。
- 详情返回链接指向明确父级路由，不仅依赖浏览器历史。
- 小屏操作区域换行，不挤压标题或产生横向页面溢出。

### 4.2 概览页

按“关键指标 → 趋势 → 需要处理的问题”组织内容。指标卡只保留名称、数值及必要口径，不把每个字段都包装成独立卡片。

- 筛选范围放在页头或指标区域上方，范围含义明确。
- 无权限、未记录和无样本不显示为零；使用“无权限”“未记录”“暂无样本”等对应状态。
- 图表有可读的时间、单位、图例或文字解释，不只通过颜色区分。
- 普通内容区纵向滚动，不为多个短区块分别制造滚动条。

### 4.3 筛选列表页

结构为：页头 → 筛选工具栏 → 结果数量与列表 → 分页。适用于会话、文档、产品及配置记录。

- 搜索、选择器、开关的高度与基线一致；选择器有下拉箭头，不伪装成操作按钮。
- 显示已归档是独立开关，默认关闭，不混入处理状态选择器。
- 搜索无结果与尚无数据分别展示；前者提供清除筛选，后者提供有权限的创建入口。
- 刷新时保留已有内容并显示忙碌状态，不反复清空列表。

### 4.4 详情与配置页

- 主从列表复用 `UiMasterDetail`，桌面列表与详情区分清楚，小屏改为单列或独立详情。
- 配置按业务分组，较长内容可使用 Tab 或折叠的进阶项，但基础项不藏在多级结构中。
- 明确区分只读、禁用和可编辑；只读内容保持可阅读、可复制。
- 保存成功、未保存修改和失败都要有明确反馈；关闭具有未保存修改的表单时遵循已确认的业务交互。

## 5. 组件规范

### 5.1 按钮、输入与选择器

- 按钮分为主操作、次操作、文字操作和危险操作，不为每个页面创造新的视觉类型。
- 主要提交按钮带动作名称，如“保存配置”“创建知识库”，避免含糊的“确定”。
- 请求执行中显示忙碌反馈并防止重复提交；失败后恢复可操作状态。
- 图标按钮有可访问名称；表格中的视觉尺寸可以紧凑，但交互区域不得过小。
- 每个输入框有可见标签，placeholder 不能替代字段名称。
- 字段错误显示在对应字段附近，使用 `aria-invalid` 和关联说明；不能只通过红框表达。
- 帮助文字说明用途、单位与限制，不重复标签，也不把内部实现细节堆到常规表单上。

### 5.2 表格与卡片

- 多字段记录优先使用表格；需要图片或组合摘要的记录可使用紧凑卡片。
- 表头基线高 44px，普通单行记录高至少 56px；多行摘要按内容自然增高。
- 列内边距采用 16px，数值列右对齐，动作列固定在右侧，标题和正文保持统一网格。
- 已选记录采用浅色背景和不影响布局的标记，不增加选中边框导致尺寸变化。
- 可点击卡片支持键盘打开与可见焦点；内部按钮不得触发父级打开或形成嵌套按钮。
- 不依赖仅 hover 时出现的关键操作；菜单打开时具有稳定定位与关闭途径。
- 长名称和 URL 不撑开布局；真实内容在详情或可访问提示中可完整读取。

### 5.3 状态标签

复用并逐步完善 `UiStatusBadge` 的语义色，不在每个页面独立写一套状态样式。

| 语义 | 色彩方向 | 例子 |
| --- | --- | --- |
| 中性 | 灰色 | 备用、已停用、已归档、只读 |
| 主要 / 当前 | 蓝色 | 当前使用、当前选中 |
| 成功 | 绿色 | 可检索、测试通过、执行完成 |
| 待处理 / 注意 | 琥珀色 | 排队中、处理中、存在待处理任务 |
| 错误 / 风险 | 红色 | 执行失败、配置异常、危险操作 |

模型配置使用“当前使用”“备用”“已停用”，不把所有非当前配置标为“已启用”。当前配置优先展示，可单独成组。业务拒答、协议异常和工具失败必须使用各自真实含义，不混用一个“失败”标签；拒答不代表系统判断答案错误。

### 5.4 弹窗、抽屉与反馈

- 复用 `UiDialog`、`UiDrawer`、`ToastNotice`，不在业务页自行实现一套遮罩与焦点管理。
- 弹窗宽度基线：小 448px、中 576px、大 896px；小屏宽度为视口减去两侧 16px。
- 长表单采用固定标题和操作区、内容区滚动；短确认弹窗不强行制造内部滚动。
- 浮层限制在可见视口内，打开不挤压页面布局；关闭恢复触发元素焦点。
- 多层弹窗按层级递增，不由各页面任意分配巨大 z-index。
- 点击遮罩、Escape、关闭按钮的行为一致；执行中是否允许关闭由具体任务决定，禁止误取消或重复提交。
- 操作成功和复制成功使用通用短提示；字段错误留在表单，不能只用一闪而过的 Toast。
- 危险操作说明确切对象与影响，遵循对应功能已经确认的删除或归档策略，不自动给所有操作增加同一确认流程。

## 6. 滚动、固定与层级

每个页面必须明确主要滚动容器。禁止用全局 `overflow: hidden` 掩盖内容，也禁止把所有页面强制变成同一种滚动方式。

| 页面类型 | 滚动约定 |
| --- | --- |
| 概览、普通配置 | 外壳内的内容区纵向滚动，页面信息完整可达 |
| 会话管理 | 页头、筛选和分页保持可见；记录区独立滚动，表头固定在记录区顶部 |
| 主从详情 | 列表和长详情可独立滚动，边界清楚；小屏避免多层纵向滚动 |
| 长表格 | 表格容器承接横向溢出，不使整个页面横向滚动 |
| 长弹窗 | 内容区滚动，标题与提交按钮不被长表单推走 |

- 限高的 flex/grid 子区域使用 `min-height: 0`，需要收缩的内容使用 `min-width: 0`。
- sticky 表头有不透明背景和正确层级，不能被记录中的操作按钮覆盖。
- 分页不放在记录滚动区域的尾部，避免滚到底部才能翻页。
- 下拉菜单位于表格或卡片滚动容器中时，必须验证不被 `overflow` 裁切；必要时使用 Portal 和定位能力。
- 滚动区域可通过键盘访问，具有可理解的区域名称；滚动不能困住键盘焦点。
- 切换详情、刷新和翻页应明确决定是否恢复或重置滚动位置，不能随机跳动。

## 7. 业务界面的补充约束

### 模型服务与 Embedding 服务

- 配置列表紧凑，突出名称、平台、模型和状态；参数细节放入编辑弹窗。
- 点击配置打开详情或编辑，避免额外重复的编辑按钮；保留明确的删除与测试入口。
- 使用现有平台 Logo 组件，不用猜测图形或 emoji 代替品牌。
- 密钥只显示服务端提供的掩码，前端不得通过获取明文再截取来实现预览。
- 平台不可修改时明确展示锁定状态及重新创建配置的方式。
- 测试结果展示真实结果与已验证的能力，不把“请求发出”显示为“测试成功”。
- Embedding 被知识库引用、维度锁定或需要重建索引时，说明实际影响，不伪装成普通可编辑参数。

### 会话管理

- 会话列表用于检索和定位，详情用于查看多轮消息，调试数据渐进展开。
- 会话、轨迹、访客 ID 的展示和复制含义明确；复制不依赖整行选中。
- 技术耗时、Token 等指标按后台用途展示；不把访客聊天页的隐藏规则套用到调试界面。
- 完整 Prompt、模型原始响应及调试信息继续遵守权限控制，不因新增组件而暴露。

### 知识库与产品管理

- 知识库及文档默认隐藏已归档记录，独立开关可查看；不通过样式删除历史数据。
- 文档处理状态与是否启用检索是不同维度，不能用一个标签代替两者。
- 多文件上传逐项展示排队、成功与失败；文件名可读，长文件名可截断但能查看完整内容。
- 产品列表、编辑表单与前台使用同一真实数据来源；未知值不能伪装成零或默认价格。
- 产品图片有尺寸、替代文本及加载失败状态；富文本预览必须净化后渲染。

### 接入、管理员与权限

- 密钥、域名、状态、配额的单位和作用范围明确，密钥生成后的一次性显示规则保持不变。
- 无权限时不展示可执行操作；服务端鉴权不能由前端隐藏代替。
- 配额未知、不限、已用尽与统计缺失分别表达，不把未知数据画成 0%。
- 权限选择保持清晰分组，提供选择数量和只读边界，不通过简化 UI 绕过授权检查。

## 8. 响应式、可访问性与动效

- 验收宽度：1440px、1024px、768px、375px；验证窄高度视口与浏览器放大。
- 断点采用 1024px、768px、480px 作为目标档位；现有断点随公共样式迁移统一，不一次性强改所有页面。
- 小屏表格可以横向滚动或改为摘要卡片；必须保留识别记录与执行操作的能力。
- 长字段自然折行；页面级横向溢出不允许，代码、表格等明确内容区除外。
- 所有操作支持键盘；不删除可见焦点，不只通过颜色表示选中或错误。
- 图标操作有名称，开关有状态，弹窗有标题；列表更新不无故抢焦点。
- 动效只反馈 hover、展开、加载或浮层状态，持续时间通常 150–200ms，不动画改变布局尺寸。
- 支持 `prefers-reduced-motion`；没有动效也能理解状态和完成任务。
- 加载中及时显示反馈；不要模拟成功、伪造进度百分比或给真实流式输出增加装饰性延迟。

## 9. 开发遵守规则

修改后台页面前，开发者应阅读本规范，并检查现有公共组件及对应页面测试。

1. 先确定页面模板与滚动容器，再开发字段和操作。
2. 优先复用公共组件；多个页面需要的变化在公共层实现，不复制组件或追加覆盖来绕过规则。
3. 颜色、间距、圆角和字号使用后台语义变量或已定义的公共类，不在页面中重复写同义规则。
4. 业务页 scoped CSS 只负责业务布局与特殊展示；不要通过全局 `h1`、`button`、`select` 选择器影响其他页面。
5. 新代码不常规使用 `!important`；确需保留的迁移例外写明原因、范围和清理条件。
6. 不为每个页面单独创建主按钮、页头、分页、弹窗或状态颜色。
7. 异常、安全、权限和未知值必须真实表达，不能为了“好看”隐藏重要信息。
8. 设计规则发生变化时，同步更新本文及公共组件；记录日期、原因、影响页面和例外。
9. 完成后说明实际修改范围、验证结果和未完成项目；代码构建通过不等于所有视觉验收已完成。
