# Agent 配置与能力管理

后台：`/admin/agent-config`，管理接口：`GET /api/admin/agent-config` 和 `PATCH /api/admin/agent-config`。

查看需要管理员 Bearer Token 和 `agent_config.read` 或 `agent_config.manage`；保存仅允许 `agent_config.manage`，默认只授予超级管理员。只读账号可查看但不能保存。接口不返回模型密钥或完整环境变量。

## 配置来源

`agent_settings` 单例数据库记录是生效配置的唯一来源。`server/config/agent.json`（或 `AGENT_CONFIG_PATH`）仅在首次初始化时提供默认值；后续重启不会覆盖管理员保存的配置。非法配置直接报错，不静默回退。

保存同时提交 `revision`、`configurationVersion` 和 `settings`。版本不匹配返回 409，不覆盖本地草稿；字段或关联约束错误返回 400。配置更新和字段差异在同一事务写入审计日志 `agent_config.updated`。每个请求捕获不可变快照，记忆读取、规划、工具执行、最终回答和异步摘要使用同一版本；轨迹保存版本及指纹。保存立即用于后续请求，不需要重启。

## 页面与可配置范围

- 基本与回答：名称、角色、人设、基础业务规则、语气与详细程度。
- 会话与记忆：欢迎语、推荐问题、近期问答轮数、摘要触发与保留轮数、摘要长度及高级读取窗口。推荐问题实时预览。
- Skills：启停已注册专项指导；元信息和详细指导只读。不预选默认 Skill，也不添加关键词分类。
- 工具能力：知识库检索、产品分类、列表、详情统一启停；同功能本地和 MCP 别名必须同时启停。停用会限制实际执行，不只是隐藏入口。
- 高级设置：规划轮数、工具次数、工具超时和结果长度。输出协议、格式校验、参数 Schema、执行顺序及内部 utils 只读。

没有启用任何 Skill 时，运行快照会自动移除 `load_skill`；基础问答仍正常工作。启停仅影响新请求可加载的指导，不删除历史消息或工具记忆。模型参数仍在模型服务配置，知识库处理参数仍由知识库管理。

页面提供未保存提示、撤销、离开确认、字段校验及保存反馈；长指导和原始规则默认折叠。

基础问答与产品咨询直接来自 `identity.persona` 和 `answeringInstructions`，不包装成默认 Skill，不通过关键词分类。模型 ID、上下文窗口和输出上限取当前模型服务，不复制到 Agent 配置。输出协议和参数校验由代码维护。

## 默认提示词与专项指导

后台展示实际生效的默认提示词、基础回答规则，以及由运行时同一构建函数生成的完整提示词预览。每轮默认提示词包含可用 Skill 摘要；模型通过 `load_skill` 按需读取详细流程。产品查询本身不要求先加载 Skill。

当前专项指导为产品咨询和售后政策；它们不包含权限、回答模式或检索开关，不会改变 Agent 默认行为边界。详细说明见 [Skills](skills.md)。

## 独立运行配置

- `runtime.allowedTools`：当前 Agent 可调用的注册工具，包含 `load_skill`。
- `runtime.maxToolCalls`：每次请求最大工具次数，默认 5。
- `runtime.maxPlannerRounds`：每次请求最大模型规划轮数，默认 6，必须大于工具次数上限，以保留最终回答机会。
- `runtime.toolTimeoutMs`：单次工具超时，默认 30000 毫秒。
- `runtime.maxToolResultChars`：单次工具文本结果上限，默认 12000 字符。

工具调用按顺序执行，Skill 加载也计入工具次数；权限、重复调用保护和预算不会因 Skill 指导变化。答案仍只做基础格式校验，不增加正确性或“本轮必须重新取证”的拒答限制。

## 同轮多工具执行

模型可在一次响应中返回多个原生 `tool_calls`，包括使用不同参数多次调用同一个工具。参数已确定的独立查询优先合并返回；执行器按模型返回顺序串行执行，不增加并发、不为每个查询重新调用模型。

- 产品 ID 已经确认时，多个 `get_product_detail` 可在同轮完成。本地和 `mcp_product_catalog_get_product_detail` 使用相同的静态调度元信息；ID 未知时先查询目录，不能提前编造后续参数。
- 不再裁剪调用数组。每个原生调用都保留 ID，并得到一条对应的工具结果；参数错误、工具失败、权限拒绝或超出预算不吞掉其他调用，仍让模型根据已返回资料决定回答或补充查询。
- `load_skill` 这类需要新指导的工具建议单独返回。若模型将它与其他调用放进同批次，先顺序执行它之前的调用及它本身；成功后，后续调用返回 `tool_requires_replanning` 和 `requiresReplanning: true`，不执行、不计工具次数、不进入重复调用记录。下一轮模型阅读指导后自行决定是否重新发起。
- 重新规划占位结果仍先检查权限、预算、工具注册及参数。真正的权限/预算错误不能通过重发绕过；若指导读取失败，则不建立成功的指导边界，剩余独立调用仍按正常校验执行。
- 轨迹保留每个调用的批次、顺序和结果，未执行的占位结果带 `deferred: true`，不被诊断为实际工具执行失败。访客进度仅展示真实尝试，不伪装执行占位步骤。

允许同轮多调用不意味着强制模型调用工具，也不保证所有模型每次都选择批量返回；直接回答、既有产品事实复用及原有调用预算保持不变。

## 唯一模型响应协议

工具只接受 OpenAI Compatible 原生 `tool_calls`，不再解析正文中的 JSON 工具指令、DSML、代码围栏或混合格式。模型自行选择调用工具或直接回答；原生多工具仍顺序执行。

规划请求固定发送 `response_format: {"type":"json_object"}`。有工具时，正文可为 `{"commentary":"我先查看产品目录。"}`；这只是公开说明，不承载调用指令。缺失、超长或格式异常的说明会忽略，不额外请求模型、不阻止有效工具调用。说明独立通过 SSE `commentary` 发送，并和 assistant 工具调用一起保存在 transcript。

无工具时，正文必须为 `{"type":"final","status":"answered","answer":"回答正文","citationIds":[],"productIds":[]}`，也可以由模型主动选择 `refused`。只检查基础格式，不验证答案业务正确性。无效正文记录 `model_protocol_error` 与失败状态，不能伪装成业务拒答。端点不支持 JSON 时明确失败，不自动去掉约束。后台测试连接验证 JSON 和原生工具两种能力，测试工具无业务副作用。

前台在工具执行前显示最新一条公开说明，步骤只显示状态，不展示耗时、参数或推理字段。已完成说明保存在历史的处理过程里；刷新依然只查询运行记录，不自动重发。第一版规划非流式，说明在规划响应完整返回后才显示，最终答案流式逻辑不变。

## 记忆语义

### 工具资料的跨轮恢复

后台「会话与记忆」提供 `memory.toolResults.enabled` 总开关，以及 `products`、`knowledge` 两个独立开关，默认均开启。开关只控制历史资料恢复，不删除审计记录、不阻止本轮工具结果，也不改变工具权限或答案格式校验。

原生工具调用仍保存标准调用/结果消息；后端产品预加载和可信业务扩展使用独立的 `RuntimeContextBlock`，不伪造模型 `tool_calls`。两类执行通过工具的显式 `contributeContext` 投影产生相同的、安全且有长度边界的资源。每个块记录来源、触发类型（model/preload/host）、会话、轨迹及时间；模型触发的块还关联原生调用 ID。块随当前轨迹的 `runtimeContextBlocks` 保存；恢复的资料不会作为新调用反复记账。失败、未执行调用和未声明投影的任意工具回包不进入有效资料记忆。

下一轮即使没有 `productIds`，也读取同一会话范围内的历史资料。产品详情按 ID、版本及当前可用状态校验；RAG 按片段、内容指纹、当前启用/归档状态和已发布索引版本检查，验证只做数据库读取，不发起 Embedding 或重新搜索。历史检索分数不是新问题的匹配分数，模型仍可以补充检索。校验失败只省略旧资料，不强制拒答。历史原生工具消息只保留结果引用，避免旧正文绕过关闭开关或失效检查；调用 ID 与配对关系仍保留。

恢复窗口沿用 `transcriptMaxTraces`，最多恢复 20 款产品和 24 个片段，正文不超过 24,000 字符、两倍单工具文本上限及输入预算的 35% 中最小者。最新记录优先，相同资源只提供一份正文；轨迹的 `contextMemory` 记录候选、恢复和省略数量。旧轨迹中的产品详情及可完整还原的 RAG 结果可以只读导入，不修改原轨迹；仅有摘要或无法还原的旧结果不会被伪装成完整资料。

未来内部业务入口可以通过 `ChatAgentContext.currentContextBlocks` / `AgentInput.initialContextBlocks` 提交可信的当前资料；块必须属于当前会话，来源工具须仍被允许。它们使用相同的保存与恢复接口。访客 HTTP DTO 不接受这些内部字段，浏览器仍只提交问题和产品关联。新增资源类型需要显式定义字段投影、有效性检查和去重键，不能把任意工具原始 JSON 自动写进上下文。

旧 Agent 配置读取时补齐默认开关，保留原并发版本及指纹，不静默覆盖数据库中的用户配置；管理员显式保存后写入新配置并审计变更。

真实接口验证（会创建并删除一个独立测试会话，实际模型用量仍正常计费）：在 `server` 目录执行 `node --env-file=../.env scripts/check-context-memory.mjs`。第二轮不携带产品 ID，检查首次模型请求已包含第一轮详情与 RAG，以及重复详情查询是否仅复用缓存。不使用浏览器。

- `recentTurns`：上下文构建器使用的最近有效问答轮数，默认 3。
- `snapshotTurns`：读取近期会话消息的窗口，默认 6，必须不小于 `recentTurns`。
- `summaryTriggerTurns`：尚未总结的消息达到多少轮后触发摘要，默认 6（一轮按用户和助手两条消息计）。
- `summaryKeepRecentTurns`：摘要保留最近多少轮原文，默认 2，必须小于触发阈值。
- `summaryMaxChars`：摘要存储和读取的字符上限，默认 1500。
- `summaryBatchMaxMessages`：单次摘要读取未总结消息的最大条数，默认 100。
- `transcriptMaxMessages` / `transcriptMaxTraces`：读取工具链记忆的消息和轨迹上限，默认 120 / 50。

摘要异步执行，不阻塞已经保存的回答。不是“每隔 6 轮重新清空上下文”，也不删除完整会话消息和轨迹。近期问答过滤拒答回复，工具 transcript 单独保留，现有格式校验和工具调度机制不变。

## 首轮对话

`GET /api/chat/presentation` 只返回 `welcome` 中的标题、说明和推荐问题。共享 ChatWorkspace 的完整助手和官网机器人均通过此接口获取配置。不会为获取欢迎语创建访客或空会话，不暴露人设、摘要指令、工具权限等内部策略。

## 验证

`server npm test`、`web npm test`、`web npm run build`。验证真实接口保存、冲突、非法配置、欢迎语立即生效及审计；浏览器验证编辑/只读权限、字段校验、冲突保留草稿与移动端布局。
