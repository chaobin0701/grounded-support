# Skills

Skills are static, versioned task policies for the Agent. A Skill describes the kind of work being done, the response rules, the tools that may be used, and execution limits. It does not call a model, access the database, or execute a tool.

## Runtime flow

```text
ChatOrchestratorService
  -> SkillSelector
  -> AgentRunner
  -> AgentLoop
  -> ToolExecutionService
```

`SkillSelector` chooses a registered Skill. Without an explicit override, the current implementation uses a small deterministic rule: product terminology selects `product_consultation`; other questions use `customer_support`. An explicit ID must already exist in `SkillRegistry`.

## Built-in Skills

- `customer_support@1.0.0`: knowledge-base grounded answers; only `search_knowledge`; at most three tool calls.
- `product_consultation@1.0.0`: product catalog answers; only product catalog tools; at most five tool calls.

The Agent still decides whether a tool is needed. The Skill only constrains what the Agent is allowed to do. `ToolPolicy` enforces the allowlist, duplicate-call protection, input validation, timeout, result size, and call limit.

## Boundaries

Skills are code-defined and statically registered in this phase. They are not editable by visitors, are not generated by the model, and do not execute arbitrary scripts. Full system instructions and tool allowlists stay internal. The selected Skill ID and version are kept in the run context snapshot for admin diagnostics.

When adding a Skill, define a `SkillDefinition`, register it in `SkillsModule`, and add a focused selector and policy test. Do not duplicate Tool Registry or Agent Loop logic inside a Skill.
